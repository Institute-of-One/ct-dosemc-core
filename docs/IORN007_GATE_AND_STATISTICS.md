## 0. まず、判断は正しい

* 非推奨になった設定（air = 30 cm）で得た合格を、古い構成に戻さず**記録して開け直した**のは正しい。
  自分で書いた §5.3.3 に自分で従った、という形になっています。
* second test の VOI で膨張係数を測り直した（**centre 5.4×、perimeter 9.4×**）のも正しい。
  first test から 1.9–4.0× を借りるという私の見積もりは甘く、実測のほうが正確です。
* 「replica SD の裏付けがない second-test の数値は、どちらの向きにも引用しない」
  というルールを立てたのは、この局面で最も重要な一手です。

そのうえで、以下は**統計を増やす前にやるべきこと**です。

---

## 1. replica SD 0.484% は本物の統計下限です（バグではない）

裏取りのため、事象数から独立に見積もりました。

centre VOI に落ちるエネルギーは 11.29 eV/放出光子 × 2×10⁸ = **2.26 GeV**。
16 cm の PMMA を経た散乱光子の 1 回あたり付与を 8–15 keV、
付与量のばらつき（CV）を 1.3–1.7 とすると：

| 平均付与 | 事象数 | 予測 σ |
|---|---|---|
| 8 keV, CV 1.7 | 2.8×10⁵ | 0.371% |
| 10 keV, CV 1.5 | 2.3×10⁵ | 0.379% |
| 15 keV, CV 1.3 | 1.5×10⁵ | 0.423% |
| **実測 replica SD** | | **0.484%** |

**一致します。**2×10⁸ ヒストリのうち、centre VOI に届いて記録される事象は
たかだか 2×10⁵ 程度です。in-run の σ = 0.010% は 10⁸ 個の独立事象を暗に仮定しており、
3 桁違います。5.4× ではなく、本質的にはこの事象数の問題です。

**結論：これは実装の欠陥ではなく、7.85 cm³ の VOI を 16 cm の PMMA 越しの散乱で
満たすという問題設定そのものが持つ床です。**追加ヒストリ以外に、centre を直接改善する手はありません。

必要倍率：

| 目標 SD | 必要ヒストリ |
|---|---|
| 0.30% | 2.6× |
| 0.25% | 3.7× |
| 0.20% | 5.9% → **5.9×** |
| 0.10% | **23.4×** |

## 2. しかし 0.10% は要りません ―― ゲートが間違っています

**±1%・4 コード平均基準は、この量に対して誤った判定基準です。**

理由は既に文書化済みの分解にあります：

```
centre 偏差 = (PENELOPE が 4 コード平均より −0.579%) × (ours vs PENELOPE)
```

**−0.579% は参照側の系統的性質であり、こちらのヒストリを増やしても動きません。**
4 コード平均を ±1% で再現せよ、という要求は
「4 つの異なる光子断面積ライブラリの平均を、そのうちの 1 つで再現せよ」と言っているのと同じです。
達成不可能というより、**意味がない**。

### 正しい基準に置き直すと、いまの数字は落ちていません

air = 44 cm での値は 4 コード平均比 −1.294%、すなわち 11.2348 eV/photon。

| 比較先 | 偏差 | σ | 有意性 |
|---|---|---|---|
| 4 コード平均 | −1.294% | — | ―― 断面積系が違うので基準にならない |
| **PENELOPE**（同一断面積系） | **−0.719%** | 0.512%* | **1.40σ** |

\* こちらの replica SD 0.484% と、PENELOPE の 36 角平均の統計 0.167%
（配布シートの per-angle 不確かさ ~1% を √36 で割った値）の二乗和。

**|ours − PENELOPE| = 0.72% は 1.40σ。有意差ではありません。**

### 推奨するゲート定義

しきい値ではなく**仮説検定**として書いてください。

```
G2 合格条件（改訂案）
  (a) 統計要件：second-test 両 VOI の replica SD が 0.25% 以下
  (b) 一致要件：|ours − PENELOPE| < 2 × 合成σ  （同一断面積系との比較）
  (c) 文脈要件：4 コード全部との偏差を併記し、
      §1 の分解（PENELOPE のオフセット × 自分の残差）を明示する
```

(a) は **3.7×** のヒストリで足ります。23.4× ではありません。
そして (a) を満たせば (b) は現状値のままで通ります（0.72% < 2 × 0.5%）。

## 3. perimeter は、ヒストリを 1 本も増やさずに 10 倍良くできます

**方位角複製（azimuthal replication）**を使ってください。

360° 全周回転後の線量場は、円柱対称ファントムでは方位角に依存しません：`D = D(r, z)`。
したがって **半径 150 mm の円周上のどこに VOI を置いても、期待値は同一**です。

perimeter VOI は直径 10 mm、置かれる円周は 2π × 150 mm = 942 mm。
**重ならない位置が 94 個取れます。**

```
94 個の方位角位置で perimeter VOI を評価し、平均する
  → 期待値は同一（対称性から厳密）
  → SD は √94 = 9.7 倍改善：0.442%  →  0.046%
  → MC の追加コストはゼロ（既存のタリーを再スコアするだけ）
```

実装は `second_test_voi_masks()` のオフセットを
`(0, R)` から `(R sin θ_m, R cos θ_m)`, m = 0…93 に回すだけです。

**しかもこれは、もう一つの独立した不確かさ推定になります。**
94 個の値の標本 SD は、replica SD と一致しなければなりません。
一致しなければ、そこに未知の系統誤差があります ――
CTDI の 4 チャンバ対称性チェックが PRNG のバグを捕まえたのと、まったく同じ構造の検定です。

> **centre には同じ手が使えません**（既に回転軸上にあり、方位角の自由度がない）。
> centre だけがヒストリを必要とします。しかし問題は半分になります。

## 4. 実行速度 ―― 4〜8 倍は無料で取れる可能性が高い

いまのスループットには説明のつかない落ち込みがあります。

| 実行 | ヒストリ/秒 |
|---|---|
| Phase-1 CTDI（1.6M ボクセル、MC-GPU 内部で 180 投影） | 6.2×10⁵ |
| G2（28.2M ボクセル、Python から 144 回起動） | **1.26×10⁵** |

**5 倍遅い。**輸送物理は同じなので、差は起動あたりのオーバーヘッドです。原因は2つ考えられます。

### 4.1 ジオメトリを 144 回読み直している

`projections_driven_externally: true` ―― 36 投影 × 4 sub-fan = **144 回の MC-GPU 起動**。
毎回 28.2M ボクセルの `.vox.gz`（ASCII 2800 万行）を読み、Woodcock テーブルを作り直しています。

**MC-GPU は CT 軌道を内部に持っています。** sub-fan は「線源方向を ψ_k だけずらし、
開口を狭めた」ものであり、MC-GPU は投影ごとに線源位置と方向を**一緒に**回します。
したがって **初期方向を ψ_k オフセットしておけば、内部軌道で 36 投影を回せます。**

```
144 回の起動  →  4 回（sub-fan ごとに1回、内部で36投影）
ジオメトリ読み込み 144 回  →  4 回
```

副次的な利点：GPU 版とまったく同じコードパスを通るので、**G5 の比較が素直になります。**

### 4.2 毎回 226 MB の線量マップを書いている

線量 ROI がファントム全体（28.2M ボクセル）なら、1 起動あたり
`dose.dat.raw` + `_PercentRelError2sigma.raw` = **2 × 113 MB = 226 MB**。
144 起動で **1 replica あたり 32 GB の書き出しと読み込み**です。

G2 で必要なのは 2 つの VOI だけです。両方を含む ROI は

```
x ∈ [−0.5, +0.5] cm,  y ∈ [−0.5, +15.5] cm,  z ∈ [−5, +5] cm
→ 4 × 64 × 40 = 10,240 ボクセル（28.2M の 1/2750）
```

**I/O が 2750 分の 1 になります。**
（first test や半径方向の診断を取るときだけ ROI を全体に戻す、というゲート別の設定に。）

### 4.3 合わせた見込み

4.1 と 4.2 で 4〜8 倍。§2 の改訂ゲートが要求する **3.7 倍のヒストリは、
CPU のまま、いまと同じ壁時計時間で到達できる可能性が高い**です。

**まず速度を測り直してください。**それから必要なヒストリ数を決めるべきで、
順序が逆になっています。

## 5. K スキャンは MC で測る問題ではありません

K = 1/2/4/8 で centre が 1.9% 振れ、トレンドなし ―― これは replica SD 0.484% から見て
**4 点の期待レンジ（≈2.06σ = 1.0%）の 2 倍**で、ほぼノイズです。K=16 を足しても
ノイズをより精密に測るだけ、という判断は正しい。

**さらに言えば、K は MC で測る量ではありません。純粋な幾何の問題です。**

sub-fan 分割は、極開口 `atan(t cos ψ / 2 SAD)` を ψ について中点則で積分する近似です。
誤差は解析的に評価でき、実際 Ω 過剰として既に測られています（K=4 で +0.07%、K=8 で +0.01%）。
**線量への影響はこの Ω 誤差で上から抑えられます。**

```
docs に「K の妥当性は解析的な立体角残差で保証される（K=4 で +0.07%）。
MC による K 収束スキャンは、この量に対しては統計ノイズしか測れないため実施しない」
と書いて、この軸を閉じてください。
```

MC の時間は centre のヒストリに回すべきです。

## 6. まとめ ―― 実行順

```
1. §5：K の軸を解析的に閉じる（計算不要、docs のみ）
2. §2：ゲートを PENELOPE 基準 + 統計要件 + 仮説検定に書き換える（計算不要）
3. §3：perimeter の方位角複製（94 位置）を実装し、既存タリーを再スコア
      ── 追加 MC ゼロ。94 位置の標本 SD が replica SD と一致するかを検定として報告
4. §4.2：線量 ROI を VOI のバウンディングボックスに絞る
5. §4.1：投影ループを MC-GPU 内部に移す（144 起動 → 4 起動）
6. 4・5 のあとスループットを再測定し、そこで初めて必要ヒストリ数を決める
7. §2(a) を満たすヒストリで G2 を再走 ── CPU で届く見込み
8. CUDA 導入 → G5（Phase 2 には GPU が必須なので、これは並行して進める）
9. Task D の残り（D2 / D3 / D4）
```

1〜4 は計算不要または再スコアのみ。**今日中に終わります。**
